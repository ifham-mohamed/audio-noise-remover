# Loudness normalization

`features/processing/loudness-normalization.ts` exports `applyLoudnessNormalization(input, sampleRate, targetLufs, options?)` returning `{ samples, metrics }`, and `measureIntegratedLoudness(input, sampleRate, options?)`. Version: `bs1770-mono-gain-v1`. Both accept non-empty canonical 48,000 Hz mono `Float32Array` PCM only. Output is newly allocated PCM of the same length; input is never written. Finite samples outside ±1 are accepted and attenuated safely. No browser audio context, model, network, filesystem, GPU or external dependency is required; the only capability is local JavaScript CPU execution.

Targets are explicit, finite, inclusive −24..−12 LUFS, matching the shared profile declaration. Loudness normalization is integrated into the shared four-stage speech pipeline used by both preview and final workers: noise removal, voice clarity, loudness normalization, and echo/reverb reduction. The pipeline validates the ordered stage list, omits disabled stages, and forwards loudness progress and metrics. The editor exposes the local CPU-safe loudness stage. Preview remains a bounded derived artifact; final success requires encoded artifact validation and retention.

Measurement uses the published 48 kHz K-weighting shelf and RLB high-pass coefficients, mono channel weight 1, complete 400 ms blocks starting at sample zero, 100 ms hops, strict −70 LUFS absolute gating, then a gate 10 LU below the absolute-gated mean. Incomplete trailing blocks are omitted from loudness only; every input sample participates in peak protection. Filter state starts at zero. No stereo energy summation, dual-mono compensation or channel conversion is performed. `channels` defaults to 1 and any other metadata value is rejected; an unlabelled interleaved array cannot be detected automatically.

Integrated LUFS is `null` for silence, input shorter than 400 ms, or no blocks above the gate, with explicit `status`. Such input is copied without loudness boost; peak safety may still attenuate it. No padding is used to invent a loudness reading. Exact silence has null peak dB values rather than negative infinity. Short transients can have measurable peaks without measurable loudness.

After the full finite-sample scan proves exact silence (`samplePeak === 0`), the meter skips FIR interpolation. Progress may jump from 0.6 to 1 in that measurement; cancellation is still checked at completion. Nonzero short and sub-gate signals retain peak estimation.

Gain is constant across the recording: the lesser of loudness gain and peak-safe gain, with no limiter, compression or sample clipping. True peak is **estimated**, using three fractional phases of a DC-normalized 24-tap Hann-windowed sinc (4× sampling), original sample maxima, and zero-padded reconstruction tails at both boundaries. A conservative 1 dB reserve is added to the estimate, and that value is capped at −1 dBTP (raw FIR estimate therefore at most −2 dBTP). A tiny additional rounding reserve protects Float32 storage. This is a CPU-safe approximation, not a certified BS.1770 Annex 2 true-peak meter or a universal bound on arbitrary continuous-time reconstruction, especially pathological near-Nyquist signals. Codec encoding, later resampling or downstream stages can increase peaks and require final artifact validation.

Output Float32 PCM is remeasured. Metrics report input/output measurements, actual `achievedLufs`, applied gain, `headroomLimited`, and `targetUnmet` (0.1 LU tolerance), with `headroom`, `unmeasurable` or `measurement-gate` reason. Absolute gating can change after scaling; the adapter reports the actual result rather than claiming the target was achieved. Peak safety wins over the target. No iterative boost or dynamics processing is used.

Options include `signal`, `onProgress(fraction)` and integer `chunkSize` (1..48000 samples; default 4800). Progress is monotonic 0..1; callbacks run synchronously at checkpoints in validation/measurement, interpolation, gain application and output measurement. An aborted signal throws an error named `AbortError` with code `CANCELLED`, including when cancellation occurs in the final callback; no partial result is returned. Callback exceptions propagate. The caller must keep the input immutable during the call, including in callbacks.

This API runs synchronously in the integrated workers. Its checkpoints handle pre-cancellation and cancellation triggered from callbacks; a newly posted worker message cannot execute during the synchronous call. For final jobs, the parent runner first obtains coordinator confirmation that the job is `cancelling`, then force-terminates the dedicated worker and confirms the terminal cancellation state. It suppresses worker results during cancellation, so the cancelled run cannot retain or publish a successful output. This final cancellation path does not depend on the loudness call yielding to worker messages.

Complexity is O(n) CPU, O(n/4800) measurement storage plus a full output buffer. This is whole-recording normalization, not a streaming API; large buffers remain constrained by browser memory and Float32 output precision.

Primary reference: [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I), Annex 1 (K weighting, gating and mono 997 Hz reference), Annex 2 (intersample peak measurement principles). The FIR here is a documented approximation rather than the Annex 2 example filter. Tests cover independent steady-state filter response, the −3.01 LKFS mono reference, both gates, duration boundaries, gain, intersample overshoot, peaks, invalid metadata, progress and cancellation. Peak reference tests evaluate analytic Hann-tapered sine waveforms at 16× sampling for 6, 12 and 18 kHz, without reusing the production FIR. These check approximation error (within 0.35 dB for those fixtures) and independent output headroom; they do not establish a universal peak bound. Qualification against the full ITU/EBU meter compliance suite or a separately qualified reference meter remains outside this adapter's claims. Only the two heavier normalization-loop tests have a bounded 20-second timeout; other tests retain the default timeout.
