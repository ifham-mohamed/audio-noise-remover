- (decision) Design a responsive local browser application with shadcn/ui and Tailwind as the foundation; the primary surface is desktop/laptop while mobile remains usable for intake, monitoring, and history.
- (decision) Use a calm studio-like visual language: deep ink surfaces, warm off-white text, one electric teal action color, and a restrained violet secondary accent for enhancement intelligence.
- (decision) Make the application workflow explicit as Intake, Enhance, Preview, Process, and History, with persistent local-only status in the shell.
- (decision) Use a two-column editor on desktop: media preview and waveform/timeline on the left, independent effect controls and output settings on the right.
- (decision) Use a single vertical workflow on small screens with sticky primary action and a bottom sheet for advanced controls.
- (decision) Represent each processing job with visible state, progress phase, cancel action, retry action, and non-color status text.
- (decision) Before/after preview is bounded, labeled Preview, and uses a synchronized waveform cursor with A/B playback controls.
- (decision) History is a local table/list with filters for status, media type, date, and profile, plus retry, reveal output, and cleanup actions.
- (decision) Settings exposes local storage, model and FFmpeg readiness, output defaults, appearance, accessibility, and cleanup controls.
- (decision) Accessibility is a first-class experience: keyboard operation, visible focus, semantic regions, live job announcements, reduced motion, non-color status, and large targets.
- (assumption) The product has no existing brand system, logo, or user research to preserve; the visual direction is an explicit first-pass proposal.
- (assumption) The primary user is a privacy-conscious person cleaning speech recordings or speech-bearing videos on a laptop.
- (question) Should the product default to dark studio mode, system appearance, or light mode on first launch?
- (question) Which waveform rendering and audio playback capabilities are available in the target browser baseline?
- (question) Should output destination selection be a browser save flow, a configured local folder, or both per platform?
