- (direction) Use the final architecture spine as the governing implementation contract for a single-repository local web application.
- (capability) CAP-1: User can import supported local audio or video media and receive validated metadata before processing.
- (capability) CAP-2: User can run speech-focused denoising and enhancement with independently controlled stages.
- (capability) CAP-3: User can preview a bounded before/after result using the selected processing profile.
- (capability) CAP-4: User can observe job progress and cancel an active run without producing a false successful output.
- (capability) CAP-5: User can retry a failed or cancelled run as a new linked attempt while originals remain immutable.
- (capability) CAP-6: User can review local processing history and access successful outputs and diagnostics.
- (capability) CAP-7: User can use the application accessibly across keyboard, screen reader, reduced-motion, and color-independent status contexts.
- (capability) CAP-8: System can support future music and mixed-audio profiles without changing the job, media, or model boundaries.
- (constraint) All media bytes, decoded audio, model inputs, temporary files, outputs, history, and logs remain local; network access is not required for a run.
- (constraint) Original inputs are immutable and every output is written through temporary-file validation and atomic rename.
- (constraint) Jobs are asynchronous typed state machines with explicit lifecycle, progress, cancellation, retry linkage, and terminal results.
- (constraint) FFmpeg owns media demux/decode/encode and the internal pipeline uses canonical PCM; AI inference is behind model ports with CPU support.
- (constraint) Shared TypeScript and Zod contracts govern browser/server, jobs, stages, persistence, capabilities, and errors.
- (constraint) Cross-platform support is capability-driven for Windows, macOS, and Linux, with documented CPU-safe fallback.
- (constraint) Cloud sync, accounts, collaboration, remote processing, pause/resume, and desktop packaging are outside the MVP contract.
- (assumption) The first release targets a local browser workflow rather than a packaged desktop shell.
- (assumption) The exact denoising and enhancement model family will be selected after fixture quality evaluation and license review.
- (question) Which concrete model family and quality thresholds must pass the fixture evaluation before release?
- (question) Which output codec/container defaults and browser playback constraints should be the product defaults per input type?
- (question) What retention and user-controlled cleanup policy should govern local history and generated artifacts?
- (event) Architecture spine absorbed; initial implementation specification decisions recorded.
- (event) Self-validation pass 1 coherence: passed; eight capabilities have intent and success, constraints bend design, non-goals are explicit, success is demonstrable, IDs are unique, and prose is lean.
- (event) Self-validation pass 2 preservation: passed; architecture spine claims are represented in the kernel or implementation-contract companion, including local-only processing, immutable originals, job lifecycle, adapters, supported formats, accessibility, recovery, and future music/mixed-audio expansion.
- (event) Spec finalized for downstream implementation.
- (decision) Choose DeepFilterNet2-derived speech denoising as the first CPU-safe model adapter candidate, subject to local ONNX conversion, fixture quality evaluation, and Apache-2.0/license verification before release.
- (decision) Set speech quality gates: median STOI improvement of at least 0.03 on noisy speech fixtures, median SI-SDR improvement of at least 3 dB, no more than 0.10 PESQ regression on clean-speech fixtures, zero clipping introduced by the pipeline, and loudness normalization within 1 LU of the configured target.
- (decision) Default audio outputs to 48 kHz WAV PCM 24-bit for lossless editing; offer FLAC, MP3 192 kbps, and M4A/AAC 192 kbps as explicit alternatives.
- (decision) Default video outputs to the source container when supported, preserve video streams without re-encoding when possible, replace the selected audio with AAC 192 kbps, and fall back to MP4 with H.264/AAC only when required by the output profile.
- (decision) Retain successful outputs until the user removes them, automatically remove previews older than 7 days, retain history metadata until the user clears it, and expose configurable cleanup controls.
- (decision) Use the File System Access API for destination selection and folder reveal when supported; otherwise use the browser save/download flow and provide Copy output path, never requiring arbitrary local path access.
- (event) Readiness blockers resolved: model strategy and quality gates, output defaults, retention policy, and browser destination behavior are now explicit.
